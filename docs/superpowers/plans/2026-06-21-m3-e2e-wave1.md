# M3 — E2E Test Suite (wave 1) — Plan

> Executes via subagent-driven-development. Build/test ONLY via xcodebuild, simulator iPhone 17. Branch `m3-e2e-tests`.

**Goal:** Make the app deterministically testable in `-uitest` mock mode (seed data so screens render content), add accessibility identifiers on core interactive elements, and write XCUITest journeys for the core flows — extending the M0 smoke test.

**Design baseline:** program spec §M3 (mock total). M0 already provides `AppLaunchEnvironment` (`-uitest`, `-uitest-auth`), mock-auth `AppState`, the boot-skip seam, the 5-tab smoke test, and tab/FAB identifiers.

## Global Constraints
- Mock mode = zero live backend. Under `-uitest`, services must return deterministic samples (no network).
- iPhone 17 simulator. `xcodebuild` only. Commit per task on `m3-e2e-tests`.
- Don't change production behavior when `-uitest` is absent.

---

### Task 1: Mock-data seam — services return deterministic samples under `-uitest`
**Files:** Modify `Sources/Core/Services/ClothingCatalogService.swift` (`fetchAll`), `Sources/Features/Wardrobe/WardrobeViewModel.swift` (load), `Sources/Features/Community/CommunityViewModel.swift` (load). Create `Sources/Core/Models/CatalogClothingItem.swift` `static let samples` if absent.
**Approach:** At the top of each load/fetch entry point, `if AppLaunchEnvironment.isUITesting { <populate published arrays with samples>; return }` before any network call. Use existing `.samples` where present; add a small `samples` array for `CatalogClothingItem` (≥2 women, ≥2 men, ≥1 unisex) if missing.
- [ ] Add `CatalogClothingItem.samples` (deterministic, no network) if not present.
- [ ] `ClothingCatalogService.fetchAll`: under `-uitest`, set womenItems/menItems/unisexItems from samples + `lastFetchedAt = .now`; return.
- [ ] `WardrobeViewModel` load: under `-uitest`, populate items from `FashionItem.samples`; return.
- [ ] `CommunityViewModel` load: under `-uitest`, populate posts from `CommunityPost.samples`/sample data; return.
- [ ] Build + run M0 smoke test (`EcrinVirtuelUITests/SmokeNavigationUITests`) — still green.
- [ ] Commit `feat(m3): mock-data seam for catalog/wardrobe/community under -uitest`.

### Task 2: Accessibility identifiers on core interactive elements
**Files:** `CatalogBrowserView`, `WardrobeView` (+ AddWardrobeItemSheet entry), `PaywallView`/`EmotionalPaywallView` (primary CTA), `ProfileView` (sign-out / delete / login rows), `QuickTryOnView` (wizard next/primary). 
- [ ] Add stable `.accessibilityIdentifier("...")` to: catalog grid container (`catalog.grid`) + first cell pattern (`catalog.cell`), wardrobe add button (`wardrobe.add`), wardrobe list/empty (`wardrobe.list`/`wardrobe.empty`), paywall primary CTA (`paywall.cta`), profile sign-out (`profile.signout`), quick-try-on primary/next (`quicktryon.primary`). Identifiers only — no logic/layout change.
- [ ] Build succeeds.
- [ ] Commit `feat(m3): accessibility identifiers on core interactive elements`.

### Task 3: E2E journeys (XCUITest)
**Files:** Create `Tests/UITests/CoreJourneysUITests.swift`.
Each test launches `["-uitest","-uitest-auth"]` and asserts real reachable elements:
- [ ] `testWardrobeTabShowsItemsAndAddSheet`: tap Garde-robe tab → `wardrobe.list`/items exist → tap `wardrobe.add` → add sheet appears.
- [ ] `testCatalogBrowserShowsItems`: from Garde-robe, open Catalogue → `catalog.grid`/`catalog.cell` exist.
- [ ] `testQuickTryOnOpensFromFab`: tap `fab.quicktryon` → QuickTryOn surface appears (`quicktryon.primary` or a known element).
- [ ] `testProfileTabShowsActions`: tap Profil → `profile.signout` exists.
- [ ] `testCommunityTabShowsPosts`: tap Communauté → at least one post/list element exists.
- [ ] Run `-only-testing:EcrinVirtuelUITests` → all green. If a screen isn't reachable in mock mode, fix the seam (Task 1) or the identifier (Task 2) — never weaken a test to assert nothing.
- [ ] Commit `test(m3): core-journey E2E tests (wardrobe/catalog/quicktryon/profile/community)`.

### Task 4: M3 wave-1 acceptance
- [ ] Full test target green (`xcodebuild test ... -scheme EcrinVirtuel`): unit suite + all UITests.

## Notes
Wave 1 covers the core navigable journeys. Data-heavy or fork-y features (MoodBoard, Gift, AR, Gaming) and deeper flows (purchase via StoreKit testing config, full wizard completion) are deferred to wave 2.
